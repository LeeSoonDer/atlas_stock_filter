# TASK CARD 10 — 活跃度地板 + 板块传导桶(第五桶)+ 席位再分配

> 丢给 Claude Code。LOADED 确认后开工。授权:第六号修正案(修正案二十至二十三)。
> **优先级:高。** 本卡修复首次运行暴露的结构性缺陷(全部候选量比低于1,产出死水标的)。
> 前置:CARD 01 至 06 已上线。可与 CARD 07/08 并行或先后,无强依赖。

## GOAL

让 Atlas 从"埋伏专家"变成"热点挖掘器 + 埋伏双引擎":杀掉死水标的,新增板块传导桶,热点逻辑占候选一半席位。

## SCOPE

### Part A — 活跃度地板(src/universe 或 src/screen/vitality)

**对全部桶生效的硬闸**,在四桶检测之后、候选选取之前执行。

1. 计算每个标的:
   * `rvol_median_10d`:近 10 日相对成交量(当日量 / 50日均量)的中位数
   * `rvol_active_days_20d`:近 20 日内 RVOL > 1.2 的天数
2. 地板判定(阈值进 `config/vitality.json`,默认从严):
   * `rvol_median_10d` ≥ 0.8
   * **且** `rvol_active_days_20d` ≥ 3
   * 两条都满足才通过
3. 未通过者:**不进候选,不进观察哨**,但在 run 元数据中统计被地板拦掉的数量(供月度复盘参考"地板是否太严")
4. **注释必须写明**:本闸与挤压桶的"相对缩量"不矛盾——挤压要的是压缩期相对自身缩量,地板要的是绝对活跃度不为零。项目所有者已明确接受"宁可错过埋伏,不要死股"的代价。

### Part B — 第五桶:板块传导(src/screen/detectors/contagion)

**三阶段检测:**

**阶段1 — 龙头异动识别(板块级)**
* 对每个板块,扫描是否存在标的满足(阈值进 config):
  - 单日涨幅 ≥ 5%(或近3日累计 ≥ 8%)
  - 当日 RVOL ≥ 3.0
  - 收盘价突破近 20 日高点
* 命中即标记该板块 `event_driven: true`,记录龙头 ticker、异动日期、涨幅、RVOL

**阶段2 — 未反应同类识别(个股级)**
* 在 `event_driven` 板块内,寻找满足以下全部条件的标的:
  - 同期涨幅显著落后龙头(如龙头涨 15%,该股 <5%)
  - 成交量已开始温和放大(RVOL ≥ 1.3,资金在试探)
  - 技术结构未破坏(价格 ≥ SMA50,或 ≥ SMA200)
  - 通过活跃度地板
* 命中者进入 `sector_contagion` 桶,记录:龙头是谁、涨幅差、板块事件时间

**阶段3 — 高波动卫星标记**
* 传导桶内标的,若同时满足:市值 < $10亿 **且** 60日 beta > 1.5(或历史波动率高于板块中位数 1.5 倍)
* 标记 `high_beta_satellite: true` + 强制风险警示
* **不得因此排除**(修正案二十:筛选宽容度原则)

**输出字段:** 每个传导候选附带 `leader_ticker`、`leader_move_pct`、`lag_gap_pct`、`sector_event_date`、`high_beta_satellite`,供 Radar 验证传导逻辑。

### Part C — 候选席位再分配(src/screen/select 修改)

现行:四桶轮询选 5 个。
**改为:**
* 板块传导桶固定占 **2 至 3 席**(有合格候选时优先填满 3 席;不足则按实际数量)
* 原四桶(动能/挤压/超卖/机构)争夺剩余 **2 至 3 席**,继续轮询
* 若传导桶本周无命中(无事件驱动板块),5 席全部由原四桶填充
* 观察哨维持 ≤8,但传导桶的次优标的优先进观察哨

### Part D — 报告与 payload

* HTML 报告:传导候选用独立视觉区分(区别于埋伏型候选),显示"龙头 XXX 涨 15% → 本标的仅涨 3%,滞后 12%"
* `high_beta_satellite` 显著红色警示
* payload 附带全部传导字段供 Radar 使用
* run 元数据含:被活跃度地板拦掉的标的数、事件驱动板块清单

## DONE-WHEN

* [ ] 活跃度地板生效:重跑上周数据,APGE/ALOT 这类量比 0.3 的标的被拦掉
* [ ] 统计输出被地板拦掉的数量,数字合理(不应超过候选池的绝大多数)
* [ ] 传导桶能识别出至少一个 event_driven 板块(用近期真实数据验证,如有龙头暴涨的板块)
* [ ] 传导候选正确记录龙头与滞后幅度
* [ ] 高波动卫星标记正确,且**未被排除**
* [ ] 席位分配:传导桶有命中时占 2-3 席;无命中时不留空席
* [ ] 报告中传导候选与埋伏候选视觉可区分

## MUST-NOT

* 因标的风险高、波动大而预先排除(违反修正案二十)
* 应用层判断传导逻辑是否成立(那是 Radar 的活)
* 引入任何付费或爬取的社交数据
* LLM 调用

## 熔断

同卡点失败 2 次 → 停止,升级包。传导桶的 beta 计算若数据不足,降级为用历史波动率替代,不阻塞。
