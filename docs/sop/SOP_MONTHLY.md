# SOP — 月度复盘仪式(每月一次,15 分钟)

> 系统的产品不是每份报告,是六个月后被数据校准过的你。本仪式就是校准发生的地方。

## 第 1 步:回填账本(5 分钟)

HTML 报告账本区列出的到期条目,逐条:

```powershell
npm run ledger:backfill -- --ticker XXXX
```

回答:重定价发生了吗 / 无效化触发了吗 / 到期无事?观察哨条目同样回填(它们没进推理也是样本——宪法前向追踪:全量归档含失败)。

## 第 2 步:看统计(3 分钟)

```powershell
npm run ledger:stats
```

四桶各自:候选数、观察哨升格数、重定价命中、无效化触发、到期无事。

## 第 3 步:固定三问(5 分钟,写进 ledger/reviews/{month}.md)

1. 本月哪一桶死亡率最高?(死亡 = 无效化触发)
2. 红队的哪些攻击被现实验证了?(翻当月 dissent 存档对照)
3. 下月改不改参数?**至多改一个**,允许不改。改则记录旧值新值 + 理由 + git tag。

## 第 4 步:金丝雀(2 分钟)

canary/ 两份冻结 payload 分别重贴 Radar 与 Red Team,对比历史输出:
* 评级方向漂移 / 缺章 / 出现编造数据或执行命令 → 记录,考虑指令加固

## 禁令

* 一次改多个参数 = 你永远不知道哪个改动起了作用
* 因单月样本调参 = overfitting 入口。四桶单月样本量都很小,趋势要看两至三个月
* 回测冲动出现时重读宪法:判断系统不可回测,前向账本是唯一法庭
